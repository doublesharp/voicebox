---
title: Incremental audio preview
description: Start long speech playback before the full render completes.
---

`POST /generate/stream` retains buffered, fully processed WAV delivery by default.
Opt into incremental preview with `?incremental=true`, `normalize: false`, and
`effects_chain: []` (which overrides profile effects). It sends validated text
chunks as they finish, with a bounded delivery buffer and crossfades. Preview
text chunks are at most 240 characters, so its prosody can differ from a final
render with a larger chunk setting.

```sh
curl --no-buffer -X POST 'http://127.0.0.1:17493/generate/stream?incremental=true' \
  -H 'Content-Type: application/json' \
  -d '{"profile_id":"YOUR_PROFILE_ID","text":"Your long script here.","normalize":false,"effects_chain":[]}' \
  --output speech-preview.wav
```

Preview uses unity gain with a peak guard. Whole-file loudness normalization,
effects and finalized export headers remain in buffered mode. The response is
PCM16 mono WAV with unknown-length RIFF/data sizes and no Content-Length;
clients must support streaming WAV/EOF termination. A client that requires a
seekable finalized WAV should use buffered mode. Engines still generate one
text chunk at a time; this does not claim token streaming or a particular
latency improvement for short inputs.

Disconnecting cancels further chunks. A connected client that stops reading
for 30 seconds also ends preview generation, so it cannot monopolize speech
inference indefinitely. An in-progress synchronous engine call is
drained before another request can use the inference resource. A synthesis error
after headers have been sent ends the stream; the client must treat incomplete
playback as a failed preview, rather than a completed export.
